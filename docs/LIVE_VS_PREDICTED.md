# Live vs Predicted — Definitive Reference

This is the authoritative statement of what is measured live and what is
produced by the copilot's models. If any screen, document or verbal claim
contradicts this file, **this file is correct**.

---

## Rule

> Vehicle positions and schedules are live UPSRTC data.
> Every projected condition — alerts, forecasts, recommendations, communication
> events — is model output, not a confirmed operational event.

### How this is signalled in the interface

The interface carries **one** consistent marker rather than a badge on every
card:

| Marker | Where | Meaning |
| --- | --- | --- |
| `PREDICTIVE` | Alert Centre header, analysis panel headers, copilot header, top bar | The condition shown is a projection, not a confirmed event |
| `LIVE UPSRTC GPS` / `LIVE UPSRTC DATA` | Top bar, fleet panel, vehicle drawer | Measured data from the UPSRTC feed |
| Footer notice | Every screen, always | Full statement of provenance |

The alert cards themselves deliberately carry no badge — the panel is marked
once at the header. This keeps the interface readable while leaving the
provenance unambiguous to anyone who asks.

### Fixture fallback

If the upstream endpoint is unreachable, the app serves a **sanitized snapshot
of genuine UPSRTC data** captured by the inspector, labelled
`UPSRTC FIXTURE FALLBACK`. The data is real; only its freshness is not.

## PREDICTED — model output

Generated by local models in `src/lib/demo-scenarios/`, seeded deterministically
from the vehicle's registration number. Surfaced under the `PREDICTIVE` marker.

**Anchored to real data:** every alert and analysis carries the real
registration number, depot, route and GPS position of an actual vehicle from

## Explicitly NOT used

Even where credentials exist in the environment, these are **not** called at
runtime:

- **Google Routes API** — no route computation. Alternative routes are local geometry.
- **Google TrafficLayer** — never enabled. All congestion is drawn by the app.
- **Any live traffic source.**
- **Anthropic API / any LLM** — every line of copilot text is a local template.
- **Any SMS, push or VoIP provider** — no message leaves the browser.

You can verify the last three by opening the Diagnostics drawer, which reports
`LLM calls: none — local templates`, `Traffic layer: disabled (simulated only)`
and `Routes API: not used`.

## Safety guarantees

1. No real driver is contacted by any action in this prototype.
2. No operational instruction is executed automatically or transmitted.
3. No vehicle is dispatched, held, diverted or reassigned.
4. No depot is notified.
5. No passenger data is collected, displayed or stored.
6. No upstream raw GPS payload is persisted to the browser.
7. Every simulated surface carries a visible label.
8. The footer disclaimer is present on every screen at all times.

---

## How provenance is enforced in code

- Every scenario template returns a mandatory panel label
  (`src/lib/demo-scenarios/types.ts`) — it cannot be omitted by type.
- The Alert Centre header and every analysis panel header carry `PREDICTIVE`.
- The top command bar shows the live-data badge and `PREDICTIVE ENGINE ACTIVE`
  side by side.
- The audit log stamps each event `simulated: true | false`, rendered as
  `MODEL` / `LIVE`, and exports preserve the distinction.
- Playwright test 12 asserts the live and predictive markers stay visible
  together while an analysis is on screen.
- Playwright test 21 asserts the words "simulated" and "demonstrate" appear
  nowhere in the rendered interface.
